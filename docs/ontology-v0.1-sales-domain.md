# AgentBI 2.0 · 销售域首版本体蓝图

这是待审核模板，而非已发布企业本体。它用于组织业务、数据与治理方共同确认第一版
`customer-order-product` 语义边界；不得在未完成真实映射前投影到 SuperSonic 或用于生产查询。

## 业务边界

首版以“销售订单行”为事实粒度，连接客户、订单、产品和组织。它回答收入、客户贡献、
产品结构、区域/组织归属等问题；库存、应收、回款、营销活动保留为后续域，通过稳定实体
关系接入，而不是复制指标口径。

## 必须由业务方确认的口径

| 项目 | 必须确认 |
| --- | --- |
| 客户 | 权威主数据系统、客户 ID、集团客户与门店/联系人层级、历史合并规则 |
| 订单 | 订单头/订单行/履约单粒度、取消与拆单合单规则、订单状态机 |
| 产品 | SKU 主键、品类层级、停售产品历史归属 |
| 组织 | 销售归属、生效区间、人员与组织变更后的历史重述策略 |
| 收入 | 含税/不含税、折扣、退款、币种、确认时点及异常订单处理 |
| 时间 | 下单、支付、发货、签收、收入确认日期各自可支持的业务问题 |

## 数据映射准入条件

发布 `2026.1` 前，每个 `DataModel` 必须提交：来源系统、库表或受治理 Dataset、主键、
增量策略、质量 SLA、字段映射、Join 条件和访问策略。每个 `Metric` 必须有唯一口径负责人。
没有物理映射的资产可以处于草稿或审核状态，不能进入 `ontology_publications`。

## 发布顺序

1. 在 Registry 保存草稿和审核意见（下一开发项）。
2. 完成真实来源映射及数据质量校验。
3. 业务负责人、数据负责人和安全负责人共同审批。
4. 创建不可变 `2026.1` 发布快照。
5. 将可执行子集投影至 SuperSonic；将全量关系投影至图数据库（后续）。

首个验收问题应是：**“本季度华东销售组织的已确认订单收入，按产品一级品类和客户区域统计”**。
它会同时检验跨实体关系、指标规则、时间口径、组织历史与行列权限。
